# BARSA SHOPI v5.6 — Deep Verification Report

## Scope
This build was audited from source and exercised with automated unit/integration tests, real Chromium execution for browser-side pixel/VideoFrame paths, real native FFmpeg CLI filter execution, MP4 probing, WebAssembly compilation checks, source integrity checks, and Android/GitHub build configuration checks.

## Fixes made during verification
1. Restored Java 17 compileOptions in `android/app/build.gradle` (this had regressed in the ZIP source).

3. Split audio preservation from Audio Clean. Users can now keep AAC audio without forcing cleanup, or enable Audio Clean independently.
4. Added v5.6 deep-verification tests for Android Java compatibility, audio control wiring, and dead/missing UI ID detection.

## Real Chromium execution
Actual source from the app was injected into Chromium 144 and run with browser-native `VideoFrame` and `OffscreenCanvas`:
- MotionBlurEngine: PASS, emitted 4 frames from a 120 -> 60 FPS temporal test, active rolling window 3 samples.
- Realtime pixel enhancement: PASS, output pixel checksum changed.
- ColorEngine CPU pass: PASS, test pixel changed from [80,110,150] to [109,139,183].
- 3D LUT parser: PASS, 2x2x2 LUT recognized as 3D.

This sandbox Chromium build exposes `VideoFrame`/`OffscreenCanvas` but does not expose `VideoEncoder`, WebGPU, or WebGL2 in headless mode, so those hardware paths cannot be honestly certified here.
