# REPORT.md — ملخص القرارات التقنية

## القرارات الملزمة وسببها

| القرار | السبب |
|---|---|
| WebCodecs كمحرك decode/encode أساسي | Hardware-accelerated مباشرة، لا حاجة لتحميل الفيديو كامل بالرام |
| WebGPU لكل تأثيرات الصورة | الأداء الوحيد الكافي لمعالجة فريم-بفريم بزمن حقيقي على الموبايل |
| WGSL مكتوب يدويًا بدل مكتبة تأثيرات جاهزة | لا توجد مكتبة WebGPU video-effects شاملة وناضجة كافية اليوم |
| ONNX Runtime Web لكل نماذج AI | الطريق الرسمي والمُوصى به من Microsoft لتشغيل ONNX في المتصفح مع WebGPU EP |
| FFmpeg.wasm كـFallback لا كأساس | لا بديل كامل له لتنوع الكودكات/الحاويات، لكنه أبطأ من WebCodecs فيجب أن يكون احتياطيًا |
| عدم شحن أي نموذج AI فعلي | بيئة البناء بلا اتصال إنترنت؛ الادّعاء بشحن نموذج غير موجود فعليًا يخالف قاعدة "لا Fake AI" |
| MediaRecorder + captureStream للتصدير الأساسي | مسار متصفح أصلي حقيقي بدون الحاجة لمكتبة muxing إضافية؛ WebM ناتج حقيقي قابل للتشغيل فورًا |

## القيود المعروفة (بصدق)

1. لم يُختبر على جهاز Android حقيقي (انظر ENGINE_TEST_REPORT.md).
2. AI Upscale وAI Frame Interpolation معطّلان افتراضيًا حتى تُضاف نماذج حقيقية.
3. Canvas2D fallback لا يدعم Sharpen/Denoise — فقط تعديلات لونية أساسية.
4. لا يوجد muxer مباشر لـMP4 خارج ffmpeg — الإخراج الأساسي WebM.
5. قياس FPS المصدر الحقيقي غير مُطبَّق (افتراض 30fps قابل للتجاوز يدويًا من المستخدم).

## الأولويات المُتبعة

معالجة الفيديو الأساسية (✅ مبني) → الدقة/Upscaling (⚠️ الكود جاهز، النموذج غير مُضمَّن) →
FPS/Interpolation (⚠️ نفس الحالة، مع Fallback حقيقي غير-AI يعمل) → الأداء (✅ Benchmark حقيقي
مبني، يحتاج معايرة على جهاز فعلي) → الجودة (✅) → تجربة الموبايل (✅ واجهة RTL بسيطة) →
التأثيرات (✅ WebGPU حقيقي) → ميزات محرر متقدمة (لم تُبنَ عمدًا، خارج الأولوية).
