# BARSA SHOPI v4.9 — Android Phase 1

## Implemented
- Native Android application shell under `android/` (minSdk 29 / targetSdk 35).
- Hardware-accelerated WebView hosts the existing Vite engine; no duplicate processing engine was created.
- Loopback local HTTP asset server adds COOP/COEP headers and streams runtime assets with HTTP chunked transfer to avoid loading WASM/ONNX assets fully into Java heap.
- Android system file chooser is wired through WebChromeClient.
- Native JavaScript bridge reports device info, keeps the screen awake during renders, provides haptic feedback, and performs bounded MP4 export.
- MP4 is streamed from the JS Blob to Android in 256 KiB chunks and published through MediaStore into `Movies/BARSA SHOPI`.
- Result UI exposes `حفظ في المعرض` only when the native bridge exists.
- Blur Studio has a dedicated `Render Blur MP4 Only` action. This bypasses Quality/Face/Color while keeping the temporal Blur/RIFE path and MP4 export configuration.
- Native-mobile CSS reduces the desktop-like presentation and gives more space to preview/workstation controls.
- GitHub Actions workflow builds/tests/audits the web engine, syncs Android assets, builds a debug APK, and uploads it as an artifact.

## Verification in this environment
- Android-specific static regression tests: 3/3 PASS.
- Source policy: PASS.
- Final audit: PASS (43 source modules / 14 critical runtime files).
- Full Node suite: 84/87 PASS; the same three environment-dependent tests cannot load `mediabunny` / `playwright` because `npm ci` cannot finish in the current sandbox.
- Android APK compilation was not possible locally because this sandbox has no Android SDK/Gradle installation and dependency installation timed out. The GitHub workflow is provided to perform the real build in CI.

## Device acceptance still required
A successful CI APK is not the same as POCO F6 acceptance. Before calling Android production-ready, test on the physical POCO F6:
1. File picker with 1080p/4K MP4.
2. WebCodecs H.264 hardware path.
3. WebGPU/WebGL/ONNX execution in the installed Android System WebView.
4. 10+ minute render thermal stability.
5. 4K tile memory pressure and cancel/restart.
6. RIFE 30→60 and 60→120.
7. Blur-only MP4 export.
8. MP4/AAC A/V sync and Gallery playback.
9. Background/foreground lifecycle behavior.
10. Automatic model download and inference self-test over device networking.
